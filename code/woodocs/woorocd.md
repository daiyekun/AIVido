## 1 阶段二：图片生成链路

> 验证时间：2026-10-08。代码结构（WBS 2.1–2.9）已基本齐备，55 项单元/接口测试通过，前端 `vite build` 成功；但按 M2 验收门（计划 §3.3）存在以下 3 项未实现 / 偏差，**M2 尚未达成**。

### 1.1 任务 2.4 —— 图片模型真实厂商适配器缺失

- **计划要求**：文生图与图 + 文字生图各至少接入 1 个真实厂商（`infrastructure/gateway/adapters/*`），真实出图成功且产物落 `ai-output`；第三方错误码映射为「可重试 / 不可重试」两类。
- **当前现状**：仅实现 3 个桩适配器，无任何真实厂商接入（grep 无 dashscope / volcengine / openai / stability / zhipu 等关键词）：
  - `stub_image.py`：本地生成一张真实 PNG 字节，模拟出图成功；
  - `stub_fail.py`：`stub_fail`（抛 `ModelCallTimeoutError`，模拟可重试超时）、`stub_fail_fatal`（抛 `AdapterNotSupportedError`，模拟不可重试）。
- **影响**：计划 §4.2 风险提示明确「若密钥未到位，可先用桩适配器完成 2.5–2.9，但 **M2 不能验收通过**」。当前端到端链路只能靠桩跑通，无法满足 M2「真实出图成功」与成功标准 3「六类能力跑通真实第三方模型」。
- **补齐计划**：
  - 前置：图片大模型 API 账号与密钥到位（计划 §8.2 最晚 W2 末）；
  - 新增至少 1 个真实图片厂商适配器（文生图 + 图生图两能力），接入统一 HTTP 客户端（超时 / 重试 / 埋点）；
  - 在后台「模型管理」新增该模型并启用，验证真实出图、错误码映射、`config_json` 密钥以环境变量名存储（`model_config.py` 已就绪）。
- **责任阶段**：阶段二（W4 前闭环，否则 M2 顺延）。

### 1.2 任务 2.6 —— 分级重试 TTL 与冻结口径不符 ✅ 已修复

- **状态**：✅ 已完成（2026-10-08）。
- **计划要求**：自动重试 3 次，延迟为 **30 秒 / 2 分钟 / 10 分钟**（计划 §1.3 冻结基线、§4.2 任务 2.6）。
- **当前现状**：`app/infrastructure/mq/topology.py` 中 `RETRY_TIER_TTL_MS` 已恢复为 `{"30s": 30_000, "2m": 120_000, "10m": 600_000}`，与 `config.py` 的 `TASK_RETRY_DELAYS=30,120,600` 对齐。

### 1.3 任务 2.5 —— 缩略图生成未实现 ✅ 已修复

- **状态**：✅ 已完成（2026-10-08）。
- **计划要求**：产物回传 MinIO 后生成缩略图，`ai-thumb` 桶可签名访问（计划 §4.2 任务 2.5 产出物「产物与缩略图 URL 均可签名访问」）。
- **当前现状**：
  - 新增 `app/infrastructure/storage/thumbnail.py`：`make_thumbnail`（Pillow 等比缩放，最长边 256，输出 JPEG）与 `thumb_key_from_output_key`（同 uuid、`.jpg` 扩展名推导缩略图 key）；
  - `workers/tasks_image.py` 产物回写后生成缩略图写入 `ai-thumb`，失败仅告警不阻断任务；
  - `task_service.py` 列表/详情接口新增 `output_thumb_urls`（10 分钟签名 URL）；前端 `Tasks.vue` 缩略图改用 `output_thumb_urls`，原图用于预览与下载；
  - 依赖新增 `pillow==11.3.0`（requirements.txt / pyproject.toml），`tests/test_thumbnail.py` 覆盖。
